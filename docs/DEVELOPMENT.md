# 開発ルール

## 共通

### 作業プロセス

- 実装依頼時に実装内容に対する不明点、懸念やリスクを洗い出し事前にユーザーに確認をとり承認を得る
- タスク完了前に品質チェック（静的解析、テスト実行）を必ず実施し全てパスさせる

### 実装

- ソフトウェア開発の以下の原則を遵守する
    - DRY
    - YAGNI
    - SOLID（特にSRP, OCPを意識する）
    - KISS

### テスト

- 実装コードに対するテストコードを必ず作成する
- テストコードは変更に強く価値のあるテストに絞る
- 単体テストはfrontendでは実装コードと同階層にテストファイルを配置（コロケーション）、backendではインソーステストとして作成する

## frontend

- コンポーネントは凝集度と結合度を意識して機能ごとに分離する
- コンポーネントロジックはカスタムフックとして積極的に切り出す
    - ただしロジックが1~3行程度のみの場合やUIに強く依存する場合はコンポーネント内に記述する
    - UI（DOM）内にロジックは含めてはならない。制御構文も消極的な利用に留める
- `useEffect`や`useRef`のような非難ハッチは必要以上に利用せず、最低限の利用に留める
- `import`文は相対パスを利用せず、path aliasによる絶対パスを利用する
- `useMemo`, `useCallback`等による手動のメモ化は避け、React Compilerの最適化に任せる
